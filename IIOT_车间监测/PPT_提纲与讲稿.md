## 第2页 项目背景与痛点

### 要讲的核心：
- 工厂车间有两类常见问题：
  1. **门窗未关/密封失效** → 车间气压突变 → 灰尘/湿度入侵 → 产品良率下降
  2. **照明浪费** → 白天开灯、无人区常亮 → 电力浪费
- 传统方案：人工巡检，不及时，依赖经验
- **我们的目标：** 传感器自动感知 → 自动响应 → MQTT远程监控，一套低成本方案

### 这一页的画面：
- 左侧：工厂车间示意（门窗开着，灰尘飘入）
- 右侧：我们的系统（传感器+风扇+灯 → 车间恢复正常）

## 第4页 硬件设计

### 选型理由（讲2-3句）：
| 元件 | 为什么选它 |
|------|-----------|
| ESP32-S3 | WiFi+蓝牙双模，I2C×2，PWM足够多，比STM32+ESP8266双芯方案简洁 |
| BMP280 | I2C接口，温压一体，精度±1hPa，能检测微小气压波动 |
| BH1750 | I2C数字光照，16bit精度，不需要ADC校准 |
| HC-SR04 | 超声波测距，2cm-4m范围，成本<3元 |
| TB6612 + 130电机 | 双路H桥驱动，PWM调速，比L298N体积小 |
| OLED 0.96" | 现场调试直观，I2C不占额外引脚 |

- 标注：I2C总线复用三设备（BMP280+BH1750+OLED），仅用2根GPIO

## 第5页 核心算法与逻辑

### 讲3个决策逻辑：

**1. 气压异常检测（自适应基准）**
```
校准阶段：启动后首次读数作为基准 P0
运行阶段：delta = |P_current - P_base| > 3hPa → 触发
慢速更新：每分钟让基准漂移5%到当前值（防漂移）
```

**2. 人员-照明联动**
```
条件1: HC-SR04距离 < 4cm  → 有人
条件2: BH1750 < 50lux     → 光线不足
两者同时满足 → LED亮 / 排风扇启动
```

**3. 风扇双触发 + 安全关**
```
触发源A: 气压突变 → 排风扇开（密封失效场景）
触发源B: 人员靠近 → 排风扇开（通风需求场景）
关闭条件: A解除 && B解除 → 排风扇关（防止反复启停）
```

## 第6页 通信与数据流

### 讲MQTT设计：
- **为什么选MQTT？** — 轻量级发布/订阅，适合嵌入式+Web双向通信
- **数据上报：** ESP32每1秒publish `sensor/data`（JSON: pressure/lux/distance/person/fan/status）
- **远程控制：** 大屏publish `cmd/fan`，ESP32订阅后执行
- **本地MQTT Broker：** Mosquitto，部署在PC端，无需云服务器

### 数据格式（放一个JSON样例）：
```json
{"pressure":1011.8, "lux":104, "distance":7, "person":true, "fan":true, "status":"person"}
```

## 讲稿要点（答辩话术）

### 开场（30秒）：
> "各位老师好，我们是第10组。我们的项目是「基于MQTT的车间智能通风与照明系统」。
> 核心思路是：用三个低成本传感器做实时监测，通过MQTT协议实现数据上云和远程控制，
> 解决车间密封失效检测和照明浪费两个实际问题。"

### 技术亮点强调（选2-3个）：
1. **自适应基准算法** — 不是写死的阈值，气压基准随环境缓慢漂移，防止温漂误报
2. **I2C总线复用** — 三设备挂在同一对SDA/SCL上，节省GPIO，接线简洁
3. **双触发+互斥关断** — 两个独立触发源都能开风扇，但只有都解除才关，避免冲突

### 遇到的最大困难（如果被问到）：
> "DHT22的驱动调试。我们尝试了4种Python/C方案都因为GPIO时序问题不稳定，
> 最终果断换I2C接口的BMP280，问题立刻解决。这个决策让我们认识到：
> 硬件选型时，协议稳定性比传感器种类更重要。"

### 结尾（15秒）：
> "整套方案物料成本不到50元，数据和控制在任意浏览器都能查看。谢谢老师，请多指教。"
